# RT Console 本地数据回放

当前已发布 [RT Console **0.0.1.21** 三平台预发行](https://github.com/RankTogether/RT-Console/releases/tag/v0.0.1.21)，将设备管理、视频、IMU 和时间分析合入同一个客户端。
安装后只有一个应用图标，主窗口通过“设备 / 数据回放”切换，不再启动第二个播放器。
Ubuntu / Windows / Android 构建与包校验通过；Windows 安装版和便携版均通过真实界面导入有效 MCAP、损坏文件报错、超过 4 GiB 偏移的稀疏 MCAP 及正常退出检查。`.21` 修复打开完成通知丢失导致进度停在 100% 的问题；稀疏文件检查不能替代现场原大文件的性能 / 内存验收。Android 手机回放和 Windows 现场无线仍待验，详见 [发布与边界](../README.md)。

Ubuntu `.14` 已修正应用列表旧名称缓存，并保留窗口缩放时的页面与视频纹理。短暂失焦不暂停回放；真正隐藏时释放解码器，返回后补画面并保持暂停。Linux 默认使用 Skia/OpenGL；仅排查渲染问题时可用 `RT_CONSOLE_LINUX_RENDERER=impeller rtcamera-finder` 作对照。

## 使用

1. 打开 **RT Console → 数据回放 → 打开 MCAP 文件**，选择电脑或手机上已下载的文件。
2. “视频”默认单路大画面，有已知布局时点击头环图上的相机 0～5 选路；桌面也可主动切换多路。切路保持时间、播放状态和倍率，不改文件或实际录制集合。
3. “IMU”选择 IMU 0 / 1 等文件中的来源，查看加速度和角速度 XYZ、单位、校正状态及固定传感器系向量；详情保留原始端口 / topic。曲线点可选，前后样本可逐条检查；IMU-only 文件也可使用。
4. “时间”查看可复制的原始纳秒、当前窗口间隔 / 频率 / 重复 / 长间隔、源视频帧的 IMU 邻点，也可选择另一 IMU 比较。窗口可选 2 / 10 / 30 秒。

默认选择可用名义 IMU 通道，允许主动切换校正通道，不混用两类来源。单位按文件显示，例如名义 `g / rad/s`、校正 `m/s² / rad/s`；无角速度或无 IMU 时明确显示缺失。向量图不是绝对姿态，不积分伪造轨迹。

数据页切到设备页会暂停并释放活动解码器，保留文件、位置和选择；返回后保持暂停。
设备页实例继续保留，切页不会重复提交正在进行的配网任务。关闭 / 换文件释放旧会话，迟到查询不能更新新文件。
直接打开本地文件不启动设备扫描或申请位置 / 蓝牙权限；设备功能仍按原有交互申请权限。

当前安装包暂不提供演示素材，请选择已有 MCAP 文件。

相机 0 / 1 / 2 / 3 / 4 / 5 对应 A1 / A2 / A3 / B1 / B2 / B3；图上弧线顺序为 0、1、2、5、4、3。IMU 0 为 linkA/imu0，IMU 1 为 linkB/imu0。新文件以自身嵌入的布局快照和 channel 元数据为准，未知 / 冲突布局保留原通道播放并提示；不会根据轨道顺序或相机数猜型号。旧文件可通过位置预设按钮临时显示头环示意，来源标为用户选择，不写回文件。IMU 未确认安装位置，用独立图例进入曲线页。

桌面快捷键：空格播放 / 暂停，左右键跳转 5 秒，Esc 退出沉浸。隐藏数据页不处理这些快捷键。
兼容命令仍进入同一 RT Console 主窗口：

```bash
rtcamera-finder --player /path/to/file.mcap
rtcamera-player /path/to/file.mcap
```

`rtcamera-player` 只是兼容启动脚本，没有单独图标 / 安装包。
便携版使用 `./rtcamera_finder --player [路径]`，Windows 使用同目录 `rtcamera_finder.exe`。
参数路径独立传入；`.mcap` 打开方式由用户选择，不覆盖其他默认程序。

## 时间读数如何解释

原始 MCAP log / publish 与已记录 payload / FPGA 时间使用整数纳秒 / BigInt 保存，复制不丢低位。
播放调度用相对微秒，精确点选 / 逐样本保存原始消息引用，不从微秒反算时间。
重复时间戳可逐条检查；时间回退和 generation / epoch 变化保留独立时钟段，不排序掩盖异常。

窗口为 `[start, end)`，统计来自原始相邻记录，独立于曲线 min/max 抽样。Median 保留半纳秒，P95 使用 nearest-rank；不是全文件分位数。
可信频率优先来自文件 header，否则足够样本时以窗口中位间隔作启发式参考。
周期偏差使用界面明示的整数纳秒参考，周期未知时只画记录间隔；长间隔不是精确丢样数。

视频比较使用“已提交纹理 / Surface 的源帧”时间，未声称测得屏幕呈现时间。
两 IMU 时间差包含采样相位；log / publish / payload 相等不表示零延迟。
**无损纳秒显示、文件时间质量、物理同步精度是三件事**，本工具不提供物理精度认证。


## 文件与平台边界

支持项目 protobuf `foxglove.CompressedVideo`、沿用的 `foxglove.CompressedImage` H.264 / H.265：Annex B、每消息一帧、无 B 帧。
IMU 支持项目实际 IMUMeasurement、CalibratedImu V1 / V2，按内嵌描述验证，不能只靠 schema 名猜字段。
支持 MCAP 未压缩 / Zstd / LZ4 分块及无索引扫描；后台建立有界索引后播放，不承诺任意大文件秒开。
坏 IMU 消息 / 轨道独立降级，容器不能安全读取时才报文件错误。无效向量不补零、不重复套标定。

桌面最多八路 / 1600 万活动像素，手机一路；原生查询 / 稀疏索引 / 解压 / GOP 都有限额。
资源不足会提示缩小范围，不把未计算部分说成完整结果。
Ubuntu 包使用随包 FFmpeg，实测为软件解码；Windows CI 已验证界面导入 / 首帧 / 时间数据和正常退出，持续回放性能与 D3D11 硬解能力仍需分别验证。
Android 使用 MediaCodec，没有 HEVC 组件时提示不支持；手机性能、单路 HEVC 和持续播放仍须真机验收。

Android 用系统文件选择器，不申请全盘存储权限。可 seek 的本地文件直接读取；特殊提供者不可随机访问时，先由用户决定是否复制临时缓存，最多 4 GiB、预留 128 MiB、可取消。
此限额不限制可 seek 本地文件总大小。关闭 / 换文件清理工具缓存，异常退出残留在下次启动清理。
后台暂停并释放活动解码器；返回后由用户继续，旋转保留会话与位置。本版手机布局有 widget 回归，新增 UI 的物理手机验证待做。

JPEG / PNG、AVCC、B 帧、损坏文件恢复、远程下载、持久最近文件、拖入、缩放 / 缩略图、手机多路、保屏和演示循环暂未交付。
文件到末尾停止；未知标定可查看通道信息，本工具不修改录制 / 参数 / 设备配置。
